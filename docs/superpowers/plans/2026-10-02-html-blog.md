# Offline HTML Blog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a searchable, responsive, offline `index.html` that presents all 180 original Markdown, HTML, and Notebook records in this repository.

**Architecture:** A Python standard-library generator scans the repository, normalizes each supported file into an article record, renders safe HTML, and writes one static page containing all content, CSS, search data, and interaction code. Local images and original HTML demos remain relative repository assets.

**Tech Stack:** Python 3 standard library, HTML5, CSS, vanilla JavaScript, `unittest`

**Spec:** `docs/superpowers/specs/2026-10-02-html-blog-design.md`

## Global Constraints

- The generated site must open directly through `file://` without a server.
- Do not add dependencies, CDN assets, frontend tooling, or remote runtime requests.
- Include the original 38 Markdown, 124 HTML, and 18 Notebook files.
- Exclude `.git`, `.superpowers`, `docs/superpowers`, and the generated root `index.html`.
- Never modify source records or execute Notebook code.
- Escape untrusted source text before placing it in the page.

## Review Focus

- Paths containing spaces, Chinese text, `+`, and `#` must remain navigable and display local assets correctly; covered by Task 2 path tests.
- Malformed UTF-8, HTML, or Notebook JSON must produce a visible per-article error instead of aborting generation; covered by Task 1 extraction tests.
- Markdown code fences and HTML source containing `</script>` must not break the generated document; covered by Task 2 escaping tests.
- Remote images in records must not create runtime network requests; covered by Task 2 remote-resource tests.
- Running the generator repeatedly must keep the record count stable and must not ingest its own output; covered by Task 3 idempotence tests.
